# ARTGAME — архитектура приложения

Держим этот файл актуальным: каждый новый тред сначала читает его.

## Цель
Единое приложение команды ARTGAME (Telegram Mini App, позже и с иконкой на телефоне). Каждый видит своё по роли. Все цифры из констант, все записи сотрудников в Google Таблицах, всё по проекту в папке проекта на Диске.

## Как устроено сейчас
| Часть | Где | Кто меняет |
|---|---|---|
| Страница приложения | `index.html` → GitHub Pages `https://raman-artgame.github.io/artgame-app/` | Claude, push в main (публикуется сама) |
| Сервер | `server/Code.gs` → Apps Script, привязан к Таблице «Журнал работ» (Диск ARTGAME HEAD, аккаунт ceo@artgame.world) | Claude, push в main → GitHub Actions `deploy-server.yml` (clasp) |
| Связь страница ↔ сервер | невидимое окно Apps Script (`/exec?bridge=1`) + postMessage; запасной прямой режим — открыть `/exec` | — |
| Вход | Telegram initData, проверка подписи токеном бота (свойство BOT_TOKEN) | — |
| Бот | @artgame_team_bot, кнопка меню → адрес страницы | HEAD в BotFather |
| Данные | Таблица «Журнал работ»: Люди, Объекты, Смены, Расходы, Справочник, Сводка, Журнал действий | приложение; HEAD руками |
| Фото и чеки | Общий Диск → ПРОЕКТЫ → год → месяц → «№ сделки · НАЗВАНИЕ — ГОРОД» → «Журнал работ (фото и чеки)» | приложение |
| Константы | «КОНСТАНТЫ ARTGAME KZ», лист «Значения» (только чтение) | тред «Утвердить финальные константы» |

Свойства скрипта: `BOT_TOKEN`, `APP_URL`, `PHOTO_FOLDER_ID`. Секретов в репозитории нет.

## Роли и зоны
Роли: Саппорт, Художник, Художник Про, Главный художник, Оператор настенного принтера, Мастер настенной печати, МОП, VIP МОП, Главный дизайнер, Помощник дизайнера, HEAD.
Зоны (допуски): Роспись, Печать, Дизайн, Продажи. У человека может быть несколько, в смене он выбирает зону. Уровень в росписи — отдельно (для печатников с допуском).
Проверяют: Главный художник — роспись, Мастер печати — печать, Главный дизайнер — дизайн, HEAD — всё, ГИП — свой объект.
Регистрация: анкета → сообщение HEAD в бот → вкладка «Команда» → роль и зоны.

## Модули (план)
1. ✅ Учёт смен и расходов, регистрация, роли.
2. Рабочие места по ролям внутри приложения (МОП, производство, художники, дизайн — сейчас отдельные артефакты), цифры из «Значений».
3. Моя оплата, КПД, скорость (м²/ч), уровень — по данным смен. Ставки видит только HEAD.
4. Склад и материалы: выдача на объект, остатки, связь с чеками.
5. Финансы: связка с финансовой таблицей.
6. Битрикс: чтение сделок (номер сделки = ID объекта), запись — только через Кодекса и «да» HEAD.
7. Единый реестр знаний и геймификация: уровни, баллы, экзамены, рейтинг.

## Правила
- Не вшивать цены и ставки — только из «Значений».
- Ничего не удалять: устаревшее — в «Архив».
- Записи в Битрикс — только через Кодекса и одобрение HEAD.
- Перед выкладкой: сквозной тест с моками Apps Script и Telegram (Playwright); после настройки сети — живой тест тестовым входом.
